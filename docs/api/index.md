## Notes on this reference

**Upstream types link out.** `intersphinx` resolves `pandas`, `numpy`, `torch`,
`pytorch_forecasting` and `pydantic` names in signatures to their own documentation — this
codebase is largely a thin, correct layer over those libraries, so knowing exactly which
`TimeSeriesDataSet` or `DataFrame` a function returns carries real explanatory weight.
Because runtime type objects stringify to their *defining* module (`pandas.core.frame.DataFrame`)
rather than their documented public name (`pandas.DataFrame`), `docs/conf.py` maps the
former onto the latter before giving up on a reference.

**`nitpicky` is off.** PYQ-233 suggests turning it on once the baseline is clean; it turns
every unresolvable type reference into an error, which is the check that keeps an autodoc
site honest as signatures change. It is not on yet because a large share of the remaining
unresolved names are upstream types whose inventories do not publish them, which would make
the gate noisy rather than informative. The build already runs under `-W --keep-going`, so
a broken cross-reference in *this* project's own docstrings fails the build today.

**Private helpers are omitted.** `_prediction_dataset`, `_evaluate_validation`,
`_window_validation_dataset` and friends carry some of the densest reasoning in the
codebase; read them in the source, or via the `[source]` links on each page.
